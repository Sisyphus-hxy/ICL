# E4-Chain 训练前核验

正式训练等数据核验结果审阅后再启动。以下小样本运行使用独立目录 `outputs/smoke`，正式训练入口默认使用 `outputs/training`。

## 全量数据

官方发布的三个训练视图全部到齐。按官方 BDDL 任务 ID 计，167 个单步任务覆盖 22 种不同的有序执行步骤序列，144 个双步任务覆盖 144 种。每个训练任务都有符合条件的跨布局配对。官方测试侧的 10 个完整双步任务保持独立留出，训练侧与测试侧的完整双步执行序列交集为零。

| 官方训练视图 | 任务 ID | RGB 演示 | 训练有向 pairs | 内部验证有向 pairs |
| --- | ---: | ---: | ---: | ---: |
| firststep | 21 | 1,050 | 39,008 | 388 |
| secondstep | 146 | 7,300 | 289,080 | 2,920 |
| selected_inverse | 144 | 7,200 | 284,208 | 2,872 |
| **合计** | **311** | **15,550** | **612,296** | **6,180** |

全部合格演示均有 RGB、原生 OSC 动作、EEF、手指状态及具名物体几何。每项任务保留官方有序执行步骤和按轨迹提取的 E0 阶段。内部训练为 13,995 条演示，内部验证为 1,555 条。分折前共有 757,574 个同任务、同 procedure、不同布局的有向配对。表中只计 donor 与 query 均属于同一折的配对。[全量核验](outputs/data_audit.json) · [逐任务统计](outputs/task_summary.csv)

冻结 JEPA 的 64 帧特征覆盖全部 15,550 条演示，复用已有 E2 缓存 50 条，新增 15,500 条。[缓存核验](outputs/cache_audit.json)

## 双卡训练链路

在物理 2、4 号 RTX 6000D 上使用 BF16/DDP，取官方训练侧一个单步开抽屉任务和一个双步开抽屉、放奶酪任务，共 100 条 RGB 演示。以初始物体布局划分 90 条训练演示和 10 条内部验证演示。可用有向配对为训练 3,960 对、验证 40 对。A、B、C 分别训练 2 个 epoch，Stage C 指标来自固定种子为每个验证 donor 抽取的一个 query，共 10 对。

| 内部验证指标 | 实测 |
| --- | ---: |
| Stage A 重建 OSC 六维动作 MAE | 0.1272 |
| Stage A 夹爪指令符号准确率 | 97.55% |
| Stage B RGB 到动作教师 latent 的 RMSE | 1.1445 |
| Stage C 同一批配对的 query latent RMSE，修正前 → 修正后 | 1.1370 → 1.0508 |
| Stage C 同一批配对的 query OSC 六维动作 MAE，修正前 → 修正后 | 0.16080 → 0.16095 |
| Stage C 残差与 donor latent 的 RMS 比值 | 0.2045 |

小样本上，残差改善了与 query 动作教师的对齐，动作误差略增。该运行支持三阶段的实现核验，迁移性能仍需正式训练验证。

训练时核对了活动模块梯度及冻结参数哈希。重载最佳 checkpoint 后，逐参数确认下游阶段的冻结模块与上游一致。单个验证双步配对可从 donor 视频特征和两端初始几何得到 192×7 的动作，直接调用 decoder 解码相加后的 latent 得到相同输出。另用预测的 EEF 和夹爪轨迹执行了一次原有 E0 tracker 控制计算。[检查结果](outputs/smoke/training/checks.json)
